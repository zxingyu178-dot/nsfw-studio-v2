# Phase 0.17 — UI 重构 + 提示词库 + 评分优化（设计草案 · 待用户确认）

> 目标来源：用户 2026-10-20 明确要求 ——「一屏工作台为主，搭配一个提示词库，每段提示词底下
> 都能看到对应已生过的图；还需要提示词优化模块（评分系统）：好的保留、差的淘汰，
> 知道好在哪（人物/服饰/场景…），AI 可以优化迭代」。
> 用户列出的高频路径：批量出图后集中审图、连续文生图+挑图、提示词/素材/配方管理、图生图迭代。
> 用户列出的痛点：三栏割裂注意力、队列/进度不直观、视觉风格不满意、尺寸选择预览图都一样。

---

## 1. 用户路径（重构必须服务这四条）

| # | 路径 | 现状摩擦 | 目标体验 |
|---|---|---|---|
| A | 连续文生图 + 挑图 | 三栏+底部任务坞来回跳；参数埋深 | 一屏内完成「改 Prompt → 生成 → 看新图 → 再改」，当前结果始终在同一视觉焦点 |
| B | 批量出图后集中审图 | 队列进度不直观；图库筛选/对比繁琐 | 底部队列条常驻可见；结果区直接支持保留/弃用/收藏/对比，不必跳图库 |
| C | 提示词/素材/配方管理 | Prompt 与它产出的图分离在两个页面 | 提示词库卡片下直接展示「这条提示词生成过的图」，可点开大图/继续生成 |
| D | 图生图迭代 | 输入图与参数分散 | 图上直接「以此图继续」，输入图槽位常驻 |

## 2. 目标信息架构

### 2.1 主屏：一屏工作台（`/generate` 重做为 Studio 主屏）

```text
┌─────────────────────────────────────────────────────────────────────┐
│ TopBar: 品牌 · 工作台 | 提示词库 | 图库 | 素材 | 设置 · Studio● Engine● │
├──────────┬──────────────────────────────────────────────┬───────────┤
│ 左栏(可收)│              中栏 Canvas                      │ 右栏(可收) │
│ 提示词库  │  ┌──────────────────────────────────────┐    │ 参数       │
│ 摘要/最近 │  │  当前结果（大图 + 左右切换 + 保留/弃用）│    │ ─ 画幅     │
│ 素材/配方 │  └──────────────────────────────────────┘    │ ─ 数量/Seed│
│          │  结果胶片条（本批全部图，点击切换）            │ ─ 高级参数 │
├──────────┴──────────────────────────────────────────────┴───────────┤
│ 队列条：当前任务 · 第 N/M · 阶段 · 进度 · 前方排队 N · 暂停/取消       │
└─────────────────────────────────────────────────────────────────────┘
```

- **一屏不滚动**：三栏总高 = 视口，各自内部滚动。
- **参数右栏分层**：常用（画幅/数量/Seed）默认展开；高级参数折叠；模块选择置顶。
- **队列条常驻**：不展开也能看到「当前阶段 + 真实 Step + 前方排队数」。
- **结果区原位审图**：保留/弃用/收藏/对比/放大 都在中栏完成，图库页面转为「全量检索/深度筛选」。

### 2.2 提示词库（升级 `/prompts`）

- 卡片列表：名称、摘要、评分徽章（综合 + 分维度）、状态（保留/候选/淘汰）、最近使用。
- **每张卡片下方展示该提示词生成过的图**（缩略图行，按时间倒序，点击进大图/恢复工作台）。
- 详情抽屉：版本时间线 → 该版本的产出图 → 评分明细 → AI 优化建议 → 「以此为父版本新建优化版本」。

## 3. 数据模型（迁移 0019+，全部软删除/可回滚）

| 表/字段 | 内容 |
|---|---|
| `prompt_evaluations`（新表） | id / prompt_id / prompt_version_id / overall_score / dimension_scores JSON（subject/clothing/scene/composition/lighting/style/quality）/ source(user\|ai) / model / notes / created_at |
| `prompts.status`（新列） | keep（保留）/ candidate（待定）/ eliminated（淘汰），附 `status_reason` |
| `prompt_version_lineage`（新表或复用 source_prompt_version_id） | 优化迭代链：child_version_id → parent_version_id + 优化说明 |
| 现有 Job→Prompt 关联 | `workbench_snapshot.source_prompt_id / source_prompt_version_id` 已存在，直接聚合出「提示词 → 图」 |

## 4. API 增量

- `GET /api/v1/prompts?include=images,score`（列表页一次拿齐卡片数据）
- `GET /api/v1/prompts/{id}/images`（按版本聚合并标出来源 Job）
- `POST /api/v1/prompts/{id}/evaluations`（写评分）
- `POST /api/v1/prompts/{id}/status`（保留/淘汰）
- `POST /api/v1/prompts/{id}/optimize`（AI 优化，返回新版本草案；需 LLM 通道，见 §7）

## 6. 尺寸预览修正（用户明确吐槽）

现状：画幅选项用统一占位视觉（`ChoiceTile` 固定 shape 只改变外框），用户感知"预览图都一样"。
目标：每个画幅给出**该比例的真实示意框**（如 2:3 竖框 / 16:9 横框），并标注实际像素
（标准/高清档），让选择前就能直观看出构图差异。

## 7. 待用户决策

1. **AI 评分/优化的模型通道**：
   - a) DeepSeek API（需 key，成本低、中文强）

3. **淘汰规则**：手动淘汰，还是「综合分低于阈值自动进候选淘汰区、人工确认后淘汰」？
4. **AGENTS 授权**：项目规则当前禁止「Agent 正式接入」；若接 LLM 做评分/优化，
   需要你明确授权并更新 AGENTS.md 条款。

## 8. 风险

- 旧 UI 有大量布局/契约测试（`GenerateLayoutVisualContract`、`GenerateNoDocumentScroll`、
  `glassPerformanceGuard` 等），重构必须同步更新，否则 CI 红。
- 评分数据是主观数据，需支持一人一标准：默认全手动，AI 只给建议不自动淘汰。
- 迁移只新增表/列，不改旧字段语义，可回滚。
