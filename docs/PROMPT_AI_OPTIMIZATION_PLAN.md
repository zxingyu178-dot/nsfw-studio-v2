# 提示词 AI 优化闭环：设计方案（待决策）

> 状态：**设计提案，未实施**（2026-10-20）。依赖用户确认 LLM 通道后再进入实现。
> 相关基线：v0.25.0（提示词 7 维人工评分 + 状态 + 排序/筛选 + 偏好记忆已上线）。

## 1. 目标

在现有「人工评分」之上，形成可验证的迭代闭环：

```
现有 Prompt/版本 → AI 生成改写候选 → 人工或规则预筛 → 对比评分 → 采纳为最新版本 → 生成图片 → 再评分
```

要解决的核心问题：用户判断「这段提示词是人物好、服饰好还是场景好」，并希望 AI 能帮忙
把差的补好、把好的保留，而不是每次手改。

## 2. 现状与缺口

| 已有 | 缺口 |
|---|---|
| 7 维人工评分（人物/服饰/场景/构图/光影/风格/画质）+ 总分 + 保留/候选/淘汰 | 无 AI 改写能力 |
| 评分排序、状态筛选、偏好记忆 | 无「候选改写」数据模型与对比 UI |
| Prompt 版本链（immutable，恢复=复制新版本） | 无 AI 产出的来源标记与可复现参数记录 |

## 3. 通道方案对比

| 方案 | 优点 | 缺点 | 适用 |
|---|---|---|---|
| A. Codex 子智能体离线批处理 | 零额外部署、已有基础设施与权限；可批量跑 | 非实时；5h 额度；内容策略受平台约束；不适合 NSFW 文案 | 先做小批量质量验证 |
| B. 本地 Ollama（如 qwen2.5 / llama3.x） | 离线、隐私最好、无内容过滤顾虑、可常驻 | 需要 GPU/内存；首次拉模型下载；质量弱于大模型 | 长期常驻方案首选 |
| C. 外部 API（OpenAI/Claude/DeepSeek 等） | 质量高、接入快 | 成本、网络、隐私与内容合规风险 | 写实类文案、非敏感场景 |
| D. ComfyUI 内置 LLM 节点 | 与生成链路同进程 | 耦合引擎、模型管理复杂 | 不推荐 |

**建议路线**：先用方案 A 对 10–20 条真实提示词做一次离线改写对比（成本低、验证"AI 改写是否真的
提升评分"）；若有效，再把通道切到 B 做常驻功能。

## 4. 数据模型（建议）

新增迁移 `0020_prompt_optimizations`（草案）：

```
prompt_optimizations
- id                TEXT PK (opt_<uuid4>)
- prompt_id         TEXT FK prompts.id
- base_version_id   TEXT FK prompt_versions.id   -- 基于哪个版本改写
- candidate_text    TEXT                        -- 改写后的正向提示词
- negative_text     TEXT NULL
- channel           TEXT                        -- codex / ollama / api / manual
- model             TEXT                        -- 模型名+版本，可复现
- params_json       TEXT                        -- temperature 等
- rationale         TEXT                        -- AI 改写理由（哪一维改了什么）
- status            TEXT                        -- CANDIDATE / ADOPTED / DISCARDED
- evaluation_id     TEXT NULL FK prompt_evaluations.id -- 采纳后关联评分
- created_at        TEXT
```

> 也可先不建表：第一轮验证用离线脚本产出 `docs/experiments/prompt-optimization-<date>.md`
> 对比表，确认有效再进入正式实现，避免过早加表。

## 5. 交互流程（正式版 UI）

1. Prompt 详情抽屉 →「AI 优化」按钮；
2. 选择改写目标维度（人物/服饰/场景/构图/光影/风格/画质，可多选）+ 风格约束；
3. 后端异步生成 1–3 个候选（复用现有任务队列或独立轻队列，禁止新增常驻服务）；
4. 候选对比视图：原文 vs 改写 diff + AI 理由 + 预估影响维度；
5. 用户「采纳」→ 复制为新 Prompt 版本（immutable 规则不变），并记录 optimization 来源；
6. 生成图片并重新评分，形成闭环数据。

## 6. 验收指标

- 改写候选被采纳率 ≥ 30%（首轮观察值）；
- 采纳后人工总分平均提升 ≥ 1 分（满分 5）的比例 ≥ 50%；
- 生成图抽检（每候选 2 张）主观不劣于原版；
- 全链路可复现：记录 channel/model/params/seed，可重跑。

## 7. 风险与约束

- **内容合规**：NSFW 提示词走平台模型可能被拒或触发策略；本地模型更合适，需在决策时确认。
- **成本**：Codex 走 Plus 5h 额度；API 按 token 计费；Ollama 一次性下载 + 本地算力。
- **质量**：AI 改写可能"看似专业但破坏原有画面主体"，必须保留人工采纳环节，不自动替换。
- **架构**：遵守「单队列 + 单 Worker、无新增常驻服务」红线；方案 B 需要一个本地 LLM 进程，
  必须登记为 ControlHub 受管对象，不能私起。
